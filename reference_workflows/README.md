# v1.1.1 参考照片与自带分镜增强包

本版修复了参考图入口不明显的问题。安装并重启服务后，浏览器按 Ctrl+F5 刷新，顶部显示“自动分镜 / 上传参考照片 / 上传自带分镜 / 先检查分镜框”。点击“上传参考照片”，在左上角“选择文件上传”处选择自己的图；没有上传时显示缺少媒体是正常的。旧自动分镜工作流不会自动长出上传节点，需要切换到新模式。

本增量包建立在 v1.0 的 ComfyUI 0.43.0 / MOSS 环境上，保留原自动分镜功能。新增三份可导入 JSON：

- **01 参考照片转漫画**：上传照片，保留原人物、服饰、视角与画面构图进行漫画化。是单幅转绘，不会自动另排一页多格。人脸、姿态和细节仍可能变化，不能承诺百分百相似。
- **02 自带分镜逐格重绘**：按已确认的矩形或多边形区域逐格参考原图生成，再放回原尺寸页面。模型负责格内绘画，合成负责框线保护。不要把“格框锁定”理解成“动作、人物、笔触逐像素复刻”。
- **03 先检查分镜区域**：不加载大模型。先检查分镜编号、区域和坐标，再运行 02。

## 安装顺序

1. 已有 v1.0 环境直接使用本包，不必重新下载四个大模型。没有环境请先按 v1.0 手册安装。
2. 关闭 ComfyUI。双击 `安装参考图增强包.bat`，输入包含 ComfyUI、python_embeded 的便携版根目录，不加引号。脚本备份已有同名节点后安装新节点和三份工作流，不改原工作流、不改核心。
3. 双击 `下载图片编辑模型.bat`，输入同一目录。新增 LoRA 仅 297,382,216 字节，放 `ComfyUI/models/loras/moss_image_edit_lora_rank_64_bf16.safetensors`。也可以从 v1.1 Release 下载同名模型后手动放置；用 `download_edit_model.py 根目录 --source 已下载文件` 验证并安装。
4. 重新启动 ComfyUI。工作流菜单中打开 `MOSS漫画/参考图与分镜`，或拖入本包 JSON。若有未知节点，检查是否运行了另一份 ComfyUI。

## 用自己的照片

打开 01，在第一个“上传参考照片”节点点击上传，选择自己的图片；修改漫画化指令后运行。保留核心识别信息，例如发型、眼镜、服装、表情、相机角度，不要同时要求换脸、换动作又保持原图不变。

默认长边 768、30 步、CFG 3、Euler/normal、shift 5、denoise 0.65。先从小图测试：长边 512。`denoise=0.35~0.55` 更接近原图，但可能保留原摄影质感；`0.6~0.8` 漫画化更明显，人物也更容易变化。低 denoise 不是人脸相似度百分比。这里使用原生 TextEncodeMOSSImageEdit + 编辑 LoRA，并且正负条件都接入同一参考图与 VAE。

照片转漫画不等于在新剧情、新动作中严格复用人物。多图角色迁移、换姿势和跨页同脸不在本版成功承诺内。图片选择清晰、主体可见、少遮挡的版本更容易控制。

## 用自己的分镜

1. 打开 03，上传已有分镜页，点击运行。它只显示检测结果，不运行 MOSS。
2. 检查每格编号。自动检测优先识别清楚闭合的四边框，可能把对白框/背景窗户误识别，也可能漏掉开口框、叠框、破框和不规则格。必须按自己的原页检查，不能把自动检测结果当作百分百正确。
3. 从“检测坐标”复制 JSON，粘贴到 02 的 `panels_json`。如不正确，先在 03 的 `panels_json` 修正并再次预览；确认后再复制到 02。留空代表每次重新自动检测，不是锁定已确认坐标。
4. 02 上传同一张原图，使用相同坐标，运行。每格按列表顺序独立生成，batch 保持 1；两格会各采样一次，六格也会各采样一次，时间随格数增加。
5. 输出保持上传页面的原始宽高，只在确认的区域内替换生成图。默认 `border_inset=4` 为框线保留内缩带；每个已声明的内嵌/叠框边界也会受保护。遮罩外的原图像素直接保留，适用于保留框线、格间距和页面留白。

**保证范围是已确认的格框及合成区域，不是 AI 格内内容。** 原图只有空格框、没有人物草稿时，模型无法知道每格动作；在各格 `prompt` 中明确写出镜头和动作。草稿有清楚的人物姿态时，用较低 denoise 强化原图关系。非常粗糙的火柴人不会自动变成严格同姿态、同身份的成稿；要更强动作控制仍需额外姿态/线稿控制与人工精修。

## 手工坐标格式

坐标为原图左上角起算的像素，x 向右、y 向下。矩形使用 `[左,上,右,下]`；多边形按边缘顺序填写点。`width/height` 为填写坐标时的原图尺寸，程序会按实际上传图尺寸同比换算。每个 polygon 至少三个点，坐标不能超出图片。列表顺序就是生成和叠放顺序，背景大格放前面，前景小格放后面。

```json
{
  "width": 768,
  "height": 1152,
  "panels": [
    {"rect": [24,24,743,720], "prompt": "A close-up of the same woman, holding a pocket watch, sad expression."},
    {"polygon": [[24,752],[743,800],[743,1127],[24,1080]], "prompt": "Her hand closes around the pocket watch. A quiet ending."}
  ]
}
```

不要直接复制原有 MOSS 的中心坐标或 yxyx JSON；本节点使用左上角像素 xy。原图尺寸、坐标和上传文件必须对应。破框头发如果要跨格保留，应把它纳入指定区域并明确层次；仅有格框并不能自动推断所有前后遮挡。

## 参数与排错

- 格框被识别错：先运行 03 修正 `panels_json`，不要反复抽卡。
- 边框被覆盖：默认内缩 4；粗框可增至 6~10。只有已经声明的边界会受到保护，未被标出的内框不是合成器已知边界。
- 原对白气泡在格内：可能被重绘；要逐字保留需将它排除在绘制区域外，或后期叠加原文字。默认不会 OCR 或自动恢复对白。
- 风格变化不明显：小幅提高 denoise，再比较相似度；不要用“更像”和“大幅改动作”互相冲突的要求。
- 画面太糊：小格采样分辨率过低会丢细节。默认每格长边 512，8GB 先保持；需要细节时逐步尝试 640/768，注意时间和显存。
- LoRA 不存在：检查文件名与 `models/loras`，然后重启。原 v1.0 不含这份编辑 LoRA。
- 未知节点：安装本增量包，重启服务，再刷新页面。只导入 JSON 不会安装 Python 节点。
- 图像数量不一致：不要人为改变列表或设置 batch>1；保持裁切、编码、采样、解码到合成的原连线。

## 已实测与限制

RTX 4070 Laptop 8GB、32GB RAM：照片长边 512、24 步、denoise 0.65 成功约 87 秒；两格分镜每格长边 384、24 步、denoise 0.4 成功约 157 秒。默认更大分辨率和更多格会更慢，这些时间不是所有电脑的速度保证。

几何测试覆盖矩形、斜四边形、三角形与内嵌叠框，检查输出尺寸不变、原输入不被修改、遮罩外像素保持一致。自动识别准确率、人物身份百分比和跨页一致性没有量化保证。
